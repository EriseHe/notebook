## 2.1 Recap

<!-- Source: Lecture 02.pdf, p. 1. -->

The preceding lecture introduced vectors and matrices, their floating-point representation, and the distinction between conditioning and stability. Conditioning is problem-dependent: it describes an intrinsic sensitivity. Stability is algorithm-dependent: it concerns avoidable additional error.

This lecture turns first to how arrays are stored and accessed, and then to solving linear systems.

## 2.2 Storing Matrices and Vectors

<!-- Source: Lecture 02.pdf, p. 2. -->

Memory can be viewed as one long string of bits. A vector is stored as a sequence of floating-point values,

$$
u_1,\ u_2,\ u_3,\ \ldots.
$$

A matrix is also stored in a linear sequence, organized by rows or by columns. The layout drawn in the lecture stores columns consecutively:

$$
\underbrace{A_{11},A_{21},A_{31},A_{41}}_{\text{first column}},
\quad
\underbrace{A_{12},A_{22},A_{32},A_{42}}_{\text{second column}},
\quad\ldots.
$$

Additional metadata records such information as the array size and allocated storage. The same block of entries can be viewed with different compatible shapes: for example, as an $m\times n\times k\times\ell$ array, an $(mn)\times(k\ell)$ matrix, or an $(mnk)\times\ell$ matrix.

The number of stored entries is unchanged; the shape determines how indices refer to those entries.

## 2.3 Algorithms and Computational Cost

<!-- Source: Lecture 02.pdf, p. 3. -->

Consider the matrix multiplication-and-addition operation

$$
A\mathrel{+}=BC,
\qquad
A\in\mathbb{K}^{\ell\times n},\quad
B\in\mathbb{K}^{\ell\times m},\quad
C\in\mathbb{K}^{m\times n}.
$$

Entrywise, the operation is

$$
A_{ik}\leftarrow A_{ik}+\sum_{j=1}^m B_{ij}C_{jk}.
$$

The lecture's `Matmuladd(A, B, C)` algorithm is the following triple loop.[^matmul-index]

```julia
for i in 1:ℓ
    for j in 1:m
        for k in 1:n
            A[i, k] += B[i, j] * C[j, k]
        end
    end
end
```

There are $\ell mn$ multiply-and-add updates. Thus the arithmetic work scales as $\ell mn$; counting multiplication and addition separately gives two arithmetic operations per update. For real scalars, this is $2\ell mn$ flops under the usual separate multiply/add convention. Complex scalars have the same $O(\ell mn)$ scaling but a different count when measured in real flops.

### 2.3.1 A Timing Comparison

The lecture fixes

$$
\ell=2\cdot10^4,\qquad m=3\cdot10^4,
$$

and records the following `@btime` results:

| Number of columns $n$ | Time recorded in the lecture |
| --- | --- |
| $1$ | Approximately $6\cdot10^{-2}$ s |
| $10^3$ | Approximately $4\cdot10^0$ s |

The arithmetic count increases by a factor of $10^3$, but the observed time increases by only about $4/0.06$. The larger operation is therefore more than ten times faster than a direct extrapolation from the first timing would predict.

These are the timings reported on the sheet, not new benchmark measurements. They motivate the question: **why does counting arithmetic operations not fully predict execution time?**

## 2.4 Floating-Point Operations and Memory Access

<!-- Source: Lecture 02.pdf, pp. 4–7. -->

### 2.4.1 Arithmetic Is Only Part of the Cost

For square matrices, another comparison on the sheet gives

$$
\begin{aligned}
\ell=m=n=10^3 &: \quad \text{approximately }7\cdot10^{-3}\text{ s},\\
\ell=m=n=10^4 &: \quad \text{approximately }6\text{ s}.
\end{aligned}
$$

An inner iteration of matrix multiplication involves arithmetic, indexing or memory access, and updating the output. The sheet emphasizes the qualitative comparison

$$
\operatorname{cost}(+)
\ll\operatorname{cost}(\times)
\ll\operatorname{cost}(\text{memory access}).
$$

This is the lecture's schematic cost comparison, not a universal ratio between hardware instruction timings. Its central point is that accessing data can be much more expensive than the floating-point arithmetic performed on that data.[^hardware-model]

### 2.4.2 RAM, Cache, and Prefetching

The simple picture of equally accessible memory is not an adequate performance model. The lecture distinguishes a large, slower memory from a small, faster **cache**.

Two possible bottlenecks are latency, the delay before requested data becomes available, and bandwidth, the rate at which data can be transferred. Prefetching attempts to reduce the effect of latency by bringing data into faster memory before it is needed.

The patterns highlighted on the sheet are fetching nearby memory and fetching memory in a predictable strided pattern. Its GPU discussion emphasizes multiple threads carrying out the same instruction on contiguous data.[^gpu-prefetch]

### 2.4.3 Loop Order Matters

Consider the matrix–vector product

$$
u=Av,
\qquad A\in\mathbb{K}^{m\times n},\quad v\in\mathbb{K}^n.
$$

Assume $u$ has been initialized to zero. Both loop orderings below perform the same exact-arithmetic updates.

**Row-oriented traversal: the column index varies in the inner loop.**

```julia
for i in 1:m
    for j in 1:n
        u[i] += A[i, j] * v[j]
    end
end
```

**Column-oriented traversal: the row index varies in the inner loop.**

```julia
for j in 1:n
    for i in 1:m
        u[i] += A[i, j] * v[j]
    end
end
```

For the column-major layout drawn in the lecture,

$$
\underbrace{A_{11},A_{21},\ldots,A_{m1}}_{j=1},
\quad
\underbrace{A_{12},A_{22},\ldots,A_{m2}}_{j=2},
\quad\ldots,
$$

the second algorithm traverses consecutive entries of $A$ in its inner loop. In the first algorithm, consecutive values of $j$ move between different columns.

The sheet counts two noncontiguous input streams in the first ordering and one in the second. It also notes the importance of this consideration for smaller matrices and vectors. These observations belong to the lecture's particular memory-access discussion; they are not a claim that one dimension-independent speedup applies to every array.

### 2.4.4 Tiling

Even when latency is well managed, memory bandwidth remains limited. For square matrix multiplication, the key observation is

$$
\underbrace{\text{arithmetic work}}_{\text{order }m^3}
\qquad\text{versus}\qquad
\underbrace{\text{stored data}}_{\text{order }m^2}.
$$

If the relevant matrices fit in cache, their entries can be reused many times after only order-$m^2$ transfers from slower memory. The question is how to retain this reuse when the full matrices are too large.

The lecture's answer is **tiling**: partition the matrices into blocks and organize the multiplication around these smaller pieces. The block diagram has the form

$$
\begin{pmatrix}
A_{11}&A_{12}&\cdots\\
A_{21}&A_{22}&\cdots\\
\vdots&\vdots&\ddots
\end{pmatrix}
=
\begin{pmatrix}
B_{11}&B_{12}&\cdots\\
B_{21}&B_{22}&\cdots\\
\vdots&\vdots&\ddots
\end{pmatrix}
\begin{pmatrix}
C_{11}&C_{12}&\cdots\\
C_{21}&C_{22}&\cdots\\
\vdots&\vdots&\ddots
\end{pmatrix},
$$

where each displayed entry now denotes a block. Thus

$$
A_{ij}=\sum_k B_{ik}C_{kj}
$$

is a matrix multiplication at the block level. The purpose is to reuse blocks while they remain in cache, rather than repeatedly transfer the same entries from slower memory.

## 2.5 Linear Systems

<!-- Source: Lecture 02.pdf, p. 8. -->

The general problem is: given

$$
A\in\mathbb{K}^{m\times n},
\qquad b\in\operatorname{range}(A)\subseteq\mathbb{K}^m,
$$

find $x\in\mathbb{K}^n$ such that

$$
Ax=b.
$$

Linear systems occur throughout mathematics. Although an invertible square system can be written as $x=A^{-1}b$, the lecture emphasizes that computing $A^{-1}$ is not necessary for solving the system.

We begin with square matrices $A\in\mathbb{K}^{m\times m}$.

> [!proposition] Equivalent conditions for a square matrix
> For $A\in\mathbb{K}^{m\times m}$, the following conditions are equivalent:
> $$
> \begin{aligned}
> \operatorname{null}(A)=\{0\}
> &\iff\text{the columns of }A\text{ are linearly independent}\\
> &\iff\operatorname{range}(A)=\mathbb{K}^m\\
> &\iff A\text{ is invertible}.
> \end{aligned}
> $$
> Such a matrix has full rank and is also called nonsingular.

The nullspace condition means that $x\mapsto Ax$ is injective. Indeed,

$$
\begin{aligned}
Ax=Ay
&\Longrightarrow A(x-y)=0\\
&\Longrightarrow x-y=0\\
&\Longrightarrow x=y.
\end{aligned}
$$

The range condition means the map is surjective. The equivalence of these conditions here relies on $A$ being square.

## 2.6 Forward and Back Substitution

<!-- Source: Lecture 02.pdf, pp. 9–10. -->

The introductory example is

$$
\begin{aligned}
x_1+5&=15,\\
x_1+5x_2&=20.
\end{aligned}
$$

The first equation gives $x_1=10$, which can then be substituted into the second equation to give $x_2=2$. The key feature is that the first equation determines $x_1$ independently of $x_2$.

### 2.6.1 Lower-Triangular Systems

For a lower-triangular matrix with nonzero diagonal entries,

$$
\begin{pmatrix}
A_{11}&0&\cdots&0\\
A_{21}&A_{22}&\ddots&\vdots\\
\vdots&\vdots&\ddots&0\\
A_{m1}&A_{m2}&\cdots&A_{mm}
\end{pmatrix}
\begin{pmatrix}x_1\\x_2\\\vdots\\x_m\end{pmatrix}
=
\begin{pmatrix}b_1\\b_2\\\vdots\\b_m\end{pmatrix},
$$

compute the unknowns in increasing order:

$$
\begin{aligned}
x_1&=\frac{b_1}{A_{11}},\\
x_2&=\frac{b_2-A_{21}x_1}{A_{22}},\\
x_3&=\frac{b_3-A_{31}x_1-A_{32}x_2}{A_{33}}.
\end{aligned}
$$

In general,

$$
\boxed{
x_i=\frac{b_i-\displaystyle\sum_{j=1}^{i-1}A_{ij}x_j}{A_{ii}},
\qquad i=1,\ldots,m.
}
$$

Every value on the right-hand side has already been computed. This is **forward substitution**.

### 2.6.2 Upper-Triangular Systems

For an upper-triangular matrix with nonzero diagonal entries, compute the unknowns in reverse order:

$$
\boxed{
x_i=\frac{b_i-\displaystyle\sum_{j=i+1}^{m}A_{ij}x_j}{A_{ii}},
\qquad i=m,m-1,\ldots,1.
}
$$

This is **back substitution**.

### 2.6.3 Row-Oriented Algorithms

The sheet gives forward and backward substitution together, with the backward-loop ranges in brackets. Written separately, they are as follows. These Julia-style transcriptions assume floating-point arrays of compatible dimensions, and $x$ is initialized as a copy of $b$.[^code-notation]

**Forward substitution:**

```julia
x = copy(b)
for i in 1:m
    for j in 1:(i - 1)
        x[i] -= A[i, j] * x[j]
    end
    x[i] /= A[i, i]
end
```

**Back substitution:**

```julia
x = copy(b)
for i in m:-1:1
    for j in (i + 1):m
        x[i] -= A[i, j] * x[j]
    end
    x[i] /= A[i, i]
end
```

### 2.6.4 Column-Oriented Variants

The variants labeled “efficient” on the sheet compute one unknown and immediately update the remaining right-hand-side entries. This organizes the matrix accesses down a column.

**Forward substitution:**

```julia
x = copy(b)
for j in 1:m
    x[j] /= A[j, j]
    for i in (j + 1):m
        x[i] -= A[i, j] * x[j]
    end
end
```

**Back substitution:**

```julia
x = copy(b)
for j in m:-1:1
    x[j] /= A[j, j]
    for i in 1:(j - 1)
        x[i] -= A[i, j] * x[j]
    end
end
```

All four algorithms assume the appropriate triangular structure and nonzero diagonal entries.

## 2.7 Gaussian Elimination

<!-- Source: Lecture 02.pdf, pp. 11–12. -->

A general matrix is not triangular. Gaussian elimination transforms its system into one that can be solved by substitution.

### 2.7.1 A Two-Equation Example

Consider

$$
\begin{aligned}
x_1+2x_2&=10,\\
2x_1+x_2&=8.
\end{aligned}
$$

Subtract twice the first equation from the second equation:[^row-operation]

$$
\begin{aligned}
(2x_1+x_2)-2(x_1+2x_2)&=8-2\cdot10,\\
\underbrace{2x_1-2x_1}_{0}+x_2-4x_2&=-12,\\
-3x_2&=-12.
\end{aligned}
$$

The equivalent triangular system is

$$
\begin{aligned}
x_1+2x_2&=10,\\
-3x_2&=-12,
\end{aligned}
\qquad\Longrightarrow\qquad
x_2=4,\quad x_1=2.
$$

In matrix form, the row operation is multiplication by

$$
L_1=
\begin{pmatrix}1&0\\-2&1\end{pmatrix}.
$$

Indeed,

$$
\begin{aligned}
\underbrace{\begin{pmatrix}1&0\\-2&1\end{pmatrix}}_{L_1}
\underbrace{\begin{pmatrix}1&2\\2&1\end{pmatrix}}_A
&=\begin{pmatrix}1&2\\0&-3\end{pmatrix},\\[4pt]
\underbrace{\begin{pmatrix}1&0\\-2&1\end{pmatrix}}_{L_1}
\underbrace{\begin{pmatrix}10\\8\end{pmatrix}}_b
&=\begin{pmatrix}10\\-12\end{pmatrix}.
\end{aligned}
$$

The same row operation must be applied to both the matrix and the right-hand side.

### 2.7.2 One Elimination Step

At step $k$, let $A$ denote the current matrix, with columns $1,\ldots,k-1$ already zero below their diagonals. Assume the current pivot $A_{kk}$ is nonzero.

> [!theorem] Theorem 1 — Elementary elimination
> Let $L_k$ be the identity matrix except for the entries
> $$
> (L_k)_{ik}=-\frac{A_{ik}}{A_{kk}},\qquad i=k+1,\ldots,m.
> $$
> Then $L_k$ is an elementary lower-triangular matrix, and $L_kA$ has zero entries below the diagonal in column $k$, while preserving the previously created zeros.

For $i>k$, the new entry in column $k$ is

$$
(L_kA)_{ik}
=A_{ik}-\frac{A_{ik}}{A_{kk}}A_{kk}
=0.
$$

The corresponding update to the trailing entries is

$$
(L_kA)_{ij}
=A_{ij}-\underbrace{\frac{A_{ik}}{A_{kk}}}_{\text{elimination multiplier}}A_{kj},
\qquad i>k,\quad j>k.
$$

These formulas express the matrix diagrams on the sheet: another column becomes triangular, and the remaining lower-right block is updated.

## 2.8 From Elimination to LU Factorization

<!-- Source: Lecture 02.pdf, p. 13. -->

Assuming elimination can proceed without a zero pivot, successive elementary lower-triangular matrices produce an upper-triangular matrix

$$
\underbrace{L_m\cdots L_1A}_{U}.
$$

The lecture includes $L_m$ in the product; its elimination column is empty, so it can be taken as the identity. For the full system, the transformation is[^missing-x]

$$
\underbrace{L_m\cdots L_1A}_{U}x=L_m\cdots L_1b.
$$

Define

$$
L=(L_m\cdots L_1)^{-1}.
$$

Then

$$
\boxed{A=LU.}
$$

The lecture ends with two questions: **is $L$ lower triangular, and can it be computed efficiently?** These are developed in Lecture 03.
