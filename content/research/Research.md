## 4.3. LinUCB-LSTDQ Joint operation

Bidirectional dependency. We connect the method in section 3 and section 4 to obtain a hierarchical learning method, LinUCB-LSTDQ, with a bi-directional coupling between two decision levels. The learners still maintain separate models, but affects the conditions under which the other learns through. In particular, we observe some coupling effect through:

- **Setup → solve:** the selected configuration determines the hierarchy and provide the setup descriptors to RL solve controller.
- **Solve → setup:** the relaxation policy determines part of the execution cost and whether the attempt succeeds, which affect the setup bandit’s feedback.

Consequently, the setup learner not only receive feedback on the cost of the configuration, but also learns which configurations work well **under the evolving solve controller**, while the solve controller learns how to apply varying strategies to different hierarchies selected by **the evolving setup learner**. This positive interaction is one substantive reason to present them as one framework. The joint method in experiment (section 7) demonstrates a higher total-time reduction than both setup-only, and solve-only methods, as well as the sum of their individual reductions, showing a superadditive saving between setup and solve learner. 

(For example, LinUCB might select a hierarchy that is cheap to construct but expensive to solve with fixed relaxation. If LSTDQ learns an effective relaxation schedule for that hierarchy, its measured cost decreases, potentially making that setup configuration more attractive to LinUCB on similar problems.)


*Setup reconfiguration*. 

For the prescribed attempt budget $J_{\max}$, we reserve one attempt for the default fallback, hence the method can have at most $J_{\max}-1$ learned attempts. In our experiments, $J_{\max}=4$, for example, permitting one initial learned attempt, up to two retries, and one default fallback if all learned attempts fail. Default has $J_{\max}=1$, while fixed-setup LSTDQ has $J_{\max}=2$, allowing one extra Default fallback. In particular, hierarchy-construction failure and solve nonconvergence both return failure feedback to the setup tuner. Previously failed exact actions are excluded within the input, and replacement candidates are ranked first by the failure score $U_n^{\rm fail}$ in Equation (3.6) and then by the runtime lower-confidence score. Retry and fallback are prescribed by the complete method $\Pi$; the Default fallback does not use learned relaxation (Section 2.1). The setup learner retains valid success/failure observations from every learned attempt. Its delayed runtime target is the assigned feedback cost $C_{t,j}^{\rm total}$ defined in Section 3.1 after success, or that cost plus the immediately following attempt's assigned cost $C_{t,j+1}^{\rm total}$ after failure (Equation (3.1)); the last failed learned attempt therefore includes the default fallback. These adjacent targets can share costs and are not independent observations. Valid setup observations remain retained even if the input ultimately fails, while the solve learner rolls back that input's cycle-time updates. Evaluation counts each executed attempt and the current problem's learner overhead once; Section 6 defines the timing windows and paired comparisons.

For the joint LinUCB–LSTDQ method, both learning phases are active from input 1 throughout the 5000-input stream (Section 6). Each branch maintains its own evolving learners. A setup-only versus joint comparison measures a difference between complete online methods $\Pi$, whose learned hierarchies may differ. The additional LSTDQ branch evaluates relaxation learning with the setup configuration held at the reference settings.
