## 

基于当前代码结构和已有数据，我会把论文主线定为：

\[ \boxed{\text{Shared LinUCB for setup}+\text{Optimistic Recursive LSTDQ for solve}} \]

但要准确表述为：

> LSTDQ 是目前最有希望的 solve controller，而不是已经证明的端到端冠军。

我不建议为了让公式看起来更对称，把 setup 的 LinUCB 换成 RLS-sandwich-LCB；也不建议当前就把 solve 主线换成 LSVI-UCB。

## 数据真正证明了什么

60³、4K 正式实验中：

|Solve 方法|Native solve|Controller|End-to-end|
|---|---|---|---|
|Fixed \(w=1.6\)|176.33 ms|0|**304.81 ms**|
|PPO|178.45 ms|7.88 ms|317.25 ms|
|Recursive MC-LCB|173.85 ms|11.01 ms|309.92 ms|
|Recursive LSTDQ-LCB|**161.58 ms**|15.51 ms|307.52 ms|

LSTDQ 相对 fixed 的 native solve 提升为 \(8.37\%\)，95% CI 为 \([7.53\%,9.18\%]\)，这是目前最强、最可信的 solve-side 信号。但 controller overhead 吃掉了收益，因此端到端仍比 fixed 慢 \(0.89\%\)。完整数据在[正式 60³/4K 记录](/Users/erisehe/Documents/GitHub/RLTune-BoomerAMG/results/joint/online_linear_lcb_v2/run_logs/joint_online_recursive_lcb_ppo_joint4k_n60_w1to3_step005_recovery_v2_20260720/README.md)。

另外还有两个限制：

- 各方法的 LinUCB 独立更新，LSTDQ 与 fixed 在 4000 个 case 中只有 26 个 exact same-setup matches，最后 500 个为零。因此 8.37% 是“联合系统轨迹”的优势，尚不是纯 solve-controller 因果效应。[same-setup audit](/Users/erisehe/Documents/GitHub/RLTune-BoomerAMG/results/joint/online_linear_lcb_v2/run_logs/joint_online_recursive_lcb_ppo_joint4k_n60_w1to3_step005_recovery_v2_20260720/same_setup_audit.json)
- 在固定 setup 的 500-case post-fit 诊断里，LSTDQ native total 为 272.43 ms，fixed 为 270.42 ms，没有表现出明确优势。[controlled result](/Users/erisehe/Documents/GitHub/RLTune-BoomerAMG/results/diagnostics/lstdq_recovery_cost/controlled500_postfit/result.json)

所以现在最准确的判断是：

\[ \boxed{\text{LSTDQ 已证明会学到更快的在线 solve 轨迹，但尚未证明它是纯控制器和端到端上的最终赢家。}} \]

## 为什么 LSTDQ 特别适合当前 BoomerAMG

你的状态已经包含 cycle position、residual gap、recent contraction、last cycle time、last weight、PDE coefficients 和 setup parameters，[状态编码器 (line 204)](/Users/erisehe/Documents/GitHub/RLTune-BoomerAMG/SolvePhase/algorithms/sarsa/online_td_lambda.py:204)因此不同 cycle 的 dynamics 可以通过状态区分，不一定需要 50 套完全独立的 \(Q_h\)。

Recursive LSTDQ 则让所有 cycle 共同学习一个 288 维 value model，并通过 eligibility trace 快速传播 terminal/recovery cost。[当前 LSTDQ 实现 (line 548)](/Users/erisehe/Documents/GitHub/RLTune-BoomerAMG/SolvePhase/algorithms/lcb/controllers.py:548)

这与 BoomerAMG 的结构很契合：

- episode 长度可变；
- 后期 cycle 样本稀少；
- residual dynamics 跨 cycle 有大量可共享结构；
- 要求每个 instance 都在线更新；
- controller wall time必须计入目标。

而现有 LSVI 将预算分给 50 个独立 stage。旧 2K checkpoint 中，前十个 stage 各约 2007 个样本，stage 20 只有 1160，stage 30 只有 122，最后几个 stage 只有 7 个左右，却仍分别拟合 160 维模型。现有实验中 LSVI native solve 为 51.61 ms、E2E 为 108.71 ms，都弱于当时的 LSTDQ；虽然协议较旧，不能当成最终裁决，但它揭示了真实的 stage sparsity 问题。[LSVI 对照结果](/Users/erisehe/Documents/GitHub/RLTune-BoomerAMG/results/joint/online_linear_lcb_v1/run_logs/joint_online_recursive_lcb_suite_2kplus2k_canonical_20260718/summary_2000.md)

经典 LSVI-UCB 的理论吸引力来自有限时域 linear MDP 假设和 elliptical bonus；但“\(Q\) 可以近似线性”并不意味着 BoomerAMG transition kernel 满足 linear-MDP 假设。[LSVI-UCB 原论文](https://proceedings.mlr.press/v125/jin20a.html)

## Setup bandit 不应为了对称而换掉

现在的 setup LinUCB 已经是 recursive least squares mean estimator；所谓 RLS-sandwich-LCB 并不会改变 mean model，只会把 uncertainty 从

\[ \sqrt{\phi^\top V^{-1}\phi} \]

换成

\[ \sqrt{\phi^\top V^{-1}MV^{-T}\phi}. \]

当前 LinUCB 借助共享 context-action features，在 288 万个 mixed BoomerAMG configurations 之间泛化；编码包含数值平方、pairwise interaction、categorical one-hot 和 mixed interactions。[action encoder (line 239)](/Users/erisehe/Documents/GitHub/RLTune-BoomerAMG/SetupPhase/learners/common/action_features.py:239) [LinUCB scoring (line 374)](/Users/erisehe/Documents/GitHub/RLTune-BoomerAMG/SetupPhase/learners/linucb/SharedLinUCB_AMG_v4.py:374)

而 setup residual 会同时混合：

- solve controller 持续学习造成的 target drift；
- hierarchy/model misspecification；
- failure/fallback shock；
- runtime noise。

把这些再写进 sandwich covariance，可能复制 LSTDQ 曾经出现的污染问题，却没有明确收益。现有 LinUCB 已把 default end-to-end 从 388.85 ms 降到约 307 ms，因此应当保留为主方法。

论文中只需说两边对齐的是决策原则，而不是 covariance 公式：

\[ \begin{aligned} \text{Setup: }&\arg\min_a\bigl(\hat c(x,a)-\alpha u_{\rm setup}(x,a)\bigr),\\ \text{Solve: }&\arg\min_a\bigl(\hat Q_c(s,a)-\beta u_{\rm solve}(s,a)\bigr). \end{aligned} \]

这就是统一的 optimistic cost minimization。

## 哪些方法可能超过当前 LSTDQ

我的机制性排序是：

1. **改进 confidence 和 overhead 的共享 Recursive LSTDQ**
    
    最可能超过当前结果。特别值得比较 current post-fit sandwich、UCLS-derived confidence、单独 coverage matrix，以及无 confidence bonus。UCLS 已经研究过 LSTD action-value 的 context-dependent confidence，并明确指出在线控制中 TD-error proxy 可能过于保守、early errors 会影响 covariance，因此你的论文不能把 “LSTD + confidence” 本身当作新算法。[UCLS 原论文](https://papers.nips.cc/paper_files/paper/2018/hash/f516dfb84b9051ed85b89cdc3a8ab7f5-Abstract.html)
    
2. **共享参数的 fitted-Q / structured model-based controller**
    
    这是长期最有可能真正超过 LSTDQ的新路线：显式学习
    
    \[ (\text{residual state},w)\rightarrow (\text{next contraction},\text{cycle time}) \]
    
    再规划 time-to-tolerance。它利用了 solver dynamics 的物理结构，可能更可解释、sample-efficient，也可能更低开销。但目前没有本地证据。
    
3. **重新校准后的 LSVI-UCB**
    
    它可以成为强 baseline，但在相同 4K online budget 下，我认为超过共享 LSTDQ 的概率较低。要公平重跑，至少要修正 60³ 的 value scale、使用当前 recovery protocol，并处理 stage sparsity。它更可能在大量 offline data 或更强 cycle-position nonstationarity 下获胜。
    
4. **重新训练的 PPO**
    
    PPO 可能在 frozen deployment 的 native solve 上超过 LSTDQ，但需要在当前 60³、当前 setup distribution 和 \([1,3]\) action range 上重训。那回答的是“有离线训练预算时谁最好”，而不是“learn-as-you-solve 谁最好”。
    
5. **Recursive MC-LCB**
    
    在短 online budget 下最不看好。完整 return 的方差高、credit assignment 慢，当前数据也只带来很小的 native gain。
    

## 最有论文价值的故事

不要把论文写成：

> We invented LSTDQ-LCB.

LSTDQ 是经典方法，[LSPI/LSTDQ 原论文](https://jmlr.org/papers/v4/lagoudakis03a.html)；LSTD confidence exploration 也已有 UCLS。更强的贡献叙事是：

> A phase-aware, fully online BoomerAMG control system uses shared LinUCB to navigate a mixed combinatorial hierarchy space and recursive LSTDQ to learn state-dependent multicycle relaxation policies, while accounting for failures, recovery, learning overhead, and end-to-end wall time.

这相对 _Learning to Relax_ 的一维 SOR 参数 bandit，问题结构明显更丰富：你既选择 multilevel hierarchy，又进行 cycle-level sequential control。[Learning to Relax](https://proceedings.iclr.cc/paper_files/paper/2024/hash/8fcc228e94aa7e4773a27c6c2d886243-Abstract-Conference.html)

现在最关键的五个实验是：

1. 固定同一批 `(instance, setup)`，比较 best fixed sweep、open-loop cycle schedule、frozen greedy LSTDQ 和正确缩放的 LSVI。
2. 加 cycle-only schedule baseline，证明 LSTDQ 的收益来自 residual/state feedback，而不只是学到了一个固定的 \(w_1,w_2,\ldots\) schedule。
3. 用当前已优化的 LSTDQ hot path重跑正式计时；现有 4K 数字尚未衡量最新精确优化。
4. 比较 no bonus、post-fit sandwich、UCLS/coverage-style confidence，并报告 calibration 与 failure rate。
5. 至少 3–5 seeds，加 held-out matrix families 和多个 grid sizes，同时分别报告 online cumulative cost 与 frozen deployment performance。

如果这些实验以后 LSTDQ仍然胜出，那么结论会很强：不是“LSTDQ碰巧跑得快”，而是：

\[ \boxed{\text{在有限在线预算下，跨 cycle 共享的递归价值学习，比 stage-wise value iteration 更适合 BoomerAMG。}} \]


---

扫描结果已经出现一个很重要的事实：相对于 HYPRE 的 `default setup + default solve`，learned setup 通常把 setup 时间砍掉 55%–65%，但代价是产生更便宜、较弱的 hierarchy，所以 solve 部分反而比 default solve 慢。也就是说，最优秀的 joint 结果不是“setup 和 solve 都分别更快”，而是 setup 的巨大节省超过了 solve 的增加；LSTDQ 的价值是把这部分 solve penalty 尽量追回来。现在我在区分 canonical recovery-v2、已被替代的 recovery-v1，以及短窗口峰值。

---

LSTDQ 不只是优化一个固定 hierarchy 上的 relaxation；它能够与 setup bandit共同适应，在廉价但多样的 BoomerAMG hierarchies 上学习不同的动态 relaxation strategy。

- Setup：`84.069 → 34.916 ms`，快 **58.47%**
- Native solve：`36.291 → 57.003 ms`，反而慢 **57.07%**
- Bandit overhead：`7.099 ms`
- 最终仍净省 `21.343 ms/case`

因此优化 bandit 的目标很明确：保持便宜的 setup，同时选择收敛质量更好的 hierarchy，降低那部分 `+20.712 ms` 的 solve 退化。这个实验同时表明，default setup组建了非常好的hierarchy，本身收敛很快。这意味着cycle数量少，于是LSTDQ 的学习收益不足以摊平控制开销；但是，因为LinUCB 产生了更动态、部分更难的 setup，有更多的cycle数量，LSTDQ 的逐 cycle adaptation 价值更大。

---

对，你看得很准。不过更准确的描述不是“从第 10 个 cycle 开始一直使用高 \(w\)”，而是：

> 两个 learner 都学出了一个接近第 9 个 AMG cycle 的强 over-relaxation 脉冲，随后根据状态在高、低 \(w\) 之间切换。

图里的纵坐标从 0 开始，所以亮带出现在 \(y\approx8\)，实际对应第 9 个 cycle。

在最后 1000 个、策略基本稳定的 instances 中：

- LinUCB v4：第 9 cycle 有 87.5% 使用 \(w\ge2.75\)，主要是 \(w=2.8\)，并不是通常用 3.0。
- LinUCB v5：第 9 cycle 有 89.5% 使用 \(w\ge2.75\)，其中 88.7% 直接使用 \(w=3.0\)。
- 两者在同一个 instance 上同时选择高 \(w\) 的比例达到 79.6%。

所以这条亮黄色横带确实是非常稳定的共同策略，不只是视觉巧合。

但第 10 cycle 之后并非持续高 \(w\)。例如第 10 cycle：

- v4：约 39.7% 选择高 \(w\)，47.3% 选择低 \(w\le1.25\)。
- v5：约 40.9% 选择高 \(w\)，52.1% 选择低 \(w\le1.25\)。

也就是说，策略更像：

\[ \text{前期中等 }w \;\rightarrow\; \text{第9 cycle 强力 }w \;\rightarrow\; \text{根据 residual 状态进行高/低修正} \]

这有点像一种“脉冲式 over-relaxation”或近似 bang-bang controller。尤其有意思的是，v4 和 v5 的 setup context 不同，但 solve learner 仍然发现了相同的宏观结构，说明第 9 cycle 附近进行一次激进修正很可能是这个 PDE/solver 组合本身的稳定特征。

不过两者也有区别：v4 后面仍然更频繁地在 \(1.2\) 和 \(2.8\) 两端摆动；v5 在脉冲之后逐渐更多采用 \(w\approx2.05\) 的中间值。这可能与 v5 后期 cycle 更少、速度更快有关，但目前只能说相关，还不能证明因果。

另外，第 9 cycle 时这批 instance 基本都还没有结束，所以这条亮带并不是“只有难题活到后面”造成的 survivor bias——它确实是一个很强的学习结果。
